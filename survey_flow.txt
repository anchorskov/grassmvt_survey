# survey_flow.txt
Trust First Survey Platform Flow

Goal
Load and publish SurveyJS JSON from JSONC files into D1 in a repeatable, auditable way and verify the survey flow end to end.

Runtime routes to keep in mind
- Canonical path: /surveys/<slug> and /api/surveys/<slug>
- Legacy /surveys/take/<slug> is compatibility-only and not the primary authoring flow.

Source of truth
Survey JSONC files live in `surveys/` and are registered in
`scripts/seed-surveys-from-jsonc.mjs` under `surveySources`.

Naming pattern for new files:
- surveys/surveys_<slug>_v<version>.jsonc

Important:
- Creating a file alone is not enough.
- Every new survey must be added to `surveySources` before seeding.

Prohibited items for Wyoming surveys
- Do not include a state dropdown or state selector on Wyoming-only surveys.
- Do not ask for Wyoming House District or Wyoming Senate District in survey questions.
- District information is derived from the user's account and address verification flow, not from survey answers.
- If a suggested survey draft includes state or district questions, leave them out unless the user explicitly tells you to keep them.

Multi-part survey metadata
Use a top-level metadata object that SurveyJS ignores:

  "x_meta": {
    "flow": "sectioned",
    "sectionExitEnabled": true,
    "sectionExitLabel": "End of section",
    "exitUrl": "/surveys"
  }

Database storage for discovery
If available, store the metadata in surveys:
- surveys.flow_type TEXT DEFAULT 'standard'
- surveys.flow_meta TEXT (JSON string)

Seed script reads x_meta and sets:
- flow_type = 'sectioned' when x_meta.flow == 'sectioned' or sectionExitEnabled == true
- flow_meta = JSON string of x_meta

Working process
1) Build the SurveyJS bundle
   - npm run build:surveyjs
2) Apply migrations locally (only when schema changed)
   - wrangler d1 migrations apply wy_local --local --config wrangler.jsonc
   - If you are only adding/updating survey JSONC content, skip this step.
3) Seed surveys from JSONC into local D1
   - node scripts/seed-surveys-from-jsonc.mjs --db=local --slug=all --version=<version> --publish=true --changelog="Seed from JSONC"
4) Verify the stored JSON and hash in local D1
   - wrangler d1 execute wy_local --command "SELECT s.slug, v.version, length(v.json_text) AS json_len, v.json_hash FROM survey_versions v JOIN surveys s ON s.id = v.survey_id ORDER BY s.slug, v.version" --local --config wrangler.jsonc
5) Start the Worker for local testing
   - npm run dev:worker
6) Confirm the surveys load in the browser
   - SurveyJS route: http://localhost:8787/surveys/<slug>
   - Example: http://localhost:8787/surveys/wy-household-economic-outlook
7) Submit a test response and confirm storage
   - Complete the survey and capture the receipt ID
   - wrangler d1 execute wy_local --command "SELECT id, survey_version_id, version_hash FROM responses ORDER BY created_at DESC LIMIT 1" --local --config wrangler.jsonc

Add a new survey (canonical)
1) Add JSONC file
   - surveys/surveys_<slug>_v<version>.jsonc
2) Register source key in seed script
   - scripts/seed-surveys-from-jsonc.mjs (`surveySources`)
3) Seed that source key
   - node scripts/seed-surveys-from-jsonc.mjs --db=local --slug=<source-key> --version=<version> --publish=true --changelog="Add <slug> v<version>"
4) Verify list discoverability
   - GET /api/surveys/list should include slug/title/status
5) Verify runtime load
   - GET /api/surveys/<slug> returns surveyJson/versionId/versionHash
   - GET /surveys/<slug> renders SurveyJS

Legacy survey_questions flow (reference only)
- /surveys/take/:slug uses survey_questions.
- Modern SurveyJS flow uses survey_versions.
- Do not use legacy flow for new survey onboarding.

Clear path to update the survey data table
SurveyJS data lives in survey_versions. Use the JSONC seed script to update it and keep hashes in sync.

1) Edit the JSONC file
   - surveys_<slug>_v<version>.jsonc
2) Rerun the seed script with a new version number or an updated changelog
   - node scripts/seed-surveys-from-jsonc.mjs --db=local --slug=<slug> --version=<version> --publish=true --changelog="Update survey wording"
3) Verify the new version row
   - wrangler d1 execute wy_local --command "SELECT s.slug, v.version, length(v.json_text) AS json_len, v.json_hash, v.published_at FROM survey_versions v JOIN surveys s ON s.id = v.survey_id WHERE s.slug = '<slug>' ORDER BY v.version DESC LIMIT 2" --local --config wrangler.jsonc

Production workflow
1) Seed JSONC into production D1
   - node scripts/seed-surveys-from-jsonc.mjs --db=prod --slug=all --version=<version> --publish=true --changelog="Seed from JSONC"
2) Verify production data
   - wrangler d1 execute wy --command "SELECT s.slug, v.version, length(v.json_text) AS json_len, v.json_hash FROM survey_versions v JOIN surveys s ON s.id = v.survey_id ORDER BY s.slug, v.version" --config wrangler.jsonc

Testing requirement
Testing is required for every change to the survey flow. Use the local checklist above to confirm:
- JSONC seeds into D1
- Survey renders at /surveys/{slug}
- Responses are stored with versionId and versionHash
