Signed-in resume implementation
- Partially implemented.
- The homepage now uses existing auth state from `/api/auth/me`.
- For signed-in users:
  - if address verification is incomplete, the continue panel points to `/account/location/`
  - if verified and survey response history exists in `/api/surveys/list`, the continue card points to the most recently updated active survey
  - if no response history exists, the continue card falls back to `/surveys/list/`

Data-model and API gaps found
- No dedicated homepage endpoint exists for:
  - last viewed Town Hall topic
  - draft Town Hall statement
  - latest receipt
  - true cross-product last activity
- `/api/surveys/list` is the only existing safe per-user source that already exposes useful resume metadata for the homepage.
- Because of that, the new continue module is survey-based rather than a broader activity timeline.

Follow-up recommendations
- Add a small last-activity API if the product needs resume behavior across surveys, Town Hall, and receipts.
- Consider exposing latest receipt metadata for signed-in users if receipt history should be a homepage return path.
- If the landing art changes again, continue using the conversion script so homepage card backgrounds stay lightweight.

Layout decisions made
- Kept the existing hero, account panel, action cards, and trust/support structure.
- Reduced overall card height and internal spacing so primary actions appear sooner.
- Increased the text measure inside cards so headings and body copy wrap more naturally.
- Reduced art dominance by shrinking image coverage to a narrower right-side area and lowering opacity.
- Made the account panel feel more unified by using a single readable content surface with a subtler integrated art strip.
- Added a small `How it works` label above the process pills and reduced their visual emphasis so they read as supporting context rather than primary actions.
- Trimmed a few body-copy lines to reduce visual density without changing meaning or links.

Full-card background pass

Exact files changed
- /home/anchor/projects/grassmvt_survey/public/index.html
- /home/anchor/projects/grassmvt_survey/public/css/site.css

How the full-card background approach was implemented
- The three primary action cards now use the existing `.webp` art as full-card backgrounds rather than a narrow side image region.
- Each card keeps the same markup structure and links, but the text and actions now sit inside a semi-opaque cream content panel layered on top of the full-card image.
- The account panel now uses a similar full-card background treatment with a single inner surface wrapper so the copy and buttons read as one anchored content panel.
- Card and account images use `background-size: cover` so the art fills the full block.
- Directional gradients were kept light enough for the art to remain visible while preserving readability under the content panels.

Background-position chosen for each card
- Survey card: `66% center`
- Town Hall card: `57% center`
- Continue card: `43% center`
- Account panel: `68% center`

Remaining visual issues after full-card background change
- Because the source art is grayscale and relatively soft, some monitors may still make the images feel quieter than intended.
- If stronger visual presence is still needed after this pass, the next step should be alternate crops or slightly higher-contrast exports from the same source files.
